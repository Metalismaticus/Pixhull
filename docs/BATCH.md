Это 603 прозрачных пикселя из 308×349: в рендере между кабиной и зеркалом просвечивает фон. Заливка этих 603 пикселей → +19 886 вокселей, жёлоб исчезает. **Давнее, не регресс:** на `dece678` числа совпадают до единицы. Гладкий меш не углубляет (2.000 против 1.999).
- **Продуктовая дыра за этим вырезом (кандидат в очередь):** `clipContestedSpikes` (`src/core/views.js`) мирит **выступы**, которые один рисунок показывает, а другой нет, и **не имеет двойника для выемок**. Выемка, которую один вид показывает, а вид по той же оси закрывает сплошняком, размазывается по всей третьей оси. **Это новая функция, меняющая геометрию, а не починка бага** — решение владельца.

### Найдено разбором жалоб владельца (всё — давнее, не регресс партии)

- **Кнопки углов задают только рыскание, но не наклон.** «Сзади» — это вид сзади-**сверху** под 26.565° (`src/main.js`, `ANGLE_CHIPS`: у «Сзади» только `yaw: 180`; `camera.pitch` не трогается, по умолчанию `PITCH_ISO_2_1`). Поэтому в нём законно видно зеркала и кромку кабины сбоку от кузова — владелец принял это за лишнюю геометрию. Замер: лишних вокселей **0** по всем шести видам; в ортографическом виде (pitch 0) модель ложится на рисунок без единого лишнего пикселя.

Примешь подсказку диалога как есть — бока становятся «верхом» и «задом», модель 3 360 885 вокселей вместо 3 174 409. Нужно распознавание шести ячеек по размерам (пары одинаковых), как уже сделано для трёх.
- **Автоподбор сетки упирается в 256** (`suggestGridSize`, `Math.min(256, need)`), хотя арту нужно 505, а в списке есть 384 и 512; и в селекте по умолчанию стоит 32³.
