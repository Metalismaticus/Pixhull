### Найдено разбором жалоб владельца (всё — давнее, не регресс партии)

- **Кнопки углов задают только рыскание, но не наклон.** «Сзади» — это вид сзади-**сверху** под 26.565° (`src/main.js`, `ANGLE_CHIPS`: у «Сзади» только `yaw: 180`; `camera.pitch` не трогается, по умолчанию `PITCH_ISO_2_1`). Поэтому в нём законно видно зеркала и кромку кабины сбоку от кузова — владелец принял это за лишнюю геометрию. Замер: лишних вокселей **0** по всем шести видам; в ортографическом виде (pitch 0) модель ложится на рисунок без единого лишнего пикселя.
- **`guessViews` на листе из шести ячеек кладёт все шесть рисунков не в свои слоты.** Запасной порядок чтения — `front, right, top, back, left, bottom` (`src/core/sheet.js`), а грузовик разложен `front, back, right, left, top, bottom`. Примешь подсказку диалога как есть — бока становятся «верхом» и «задом», модель 3 360 885 вокселей вместо 3 174 409. Нужно распознавание шести ячеек по размерам (пары одинаковых), как уже сделано для трёх.
- **Автоподбор сетки упирается в 256** (`suggestGridSize`, `Math.min(256, need)`), хотя арту нужно 505, а в списке есть 384 и 512; и в селекте по умолчанию стоит 32³. Из-за этого скругление кабины (5 px на кабине 246 px) выходит квадратом: ступени появляются с 160, читаются с 192–256 (3 из 5), полностью — только на 512. Само по себе скругление — **предел сетки, не дефект** (залит 1 пиксель, съедено 12; числа на `dece678` и сейчас совпадают на всех десяти сетках).
- **Просьба владельца (новая функция):** порог слияния — ползунком, чтобы выбирал художник, с живым счётом «освободится N слотов»; по умолчанию остаётся 1.0. План считается за 6.9 мс на полной палитре. **Владелец решил: в очередь** (2026-09-24), не в текущую партию.
