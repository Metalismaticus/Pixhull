# Окно модели: режим рисунка, переключение 2D и 3D

Спецификация к пункту 3 партии (`docs/BATCH.md`), очередь 3 в `docs/ROADMAP.md`,
раздел «Правка вида прямо в приложении». Источники правил: `docs/DESIGN.md`
целиком, `docs/DECISIONS.md` («Редактор», «Сетка и форматы», «Скорость и
потоки»), принятые спецификации `docs/specs/2026-09-24-6-left-panel.md`,
`…-2-box-and-grid.md`, `…-3-disagreement-map.md`. Макета в `design/mockups/`
нет (папки нет вовсе); образец — `index.html`, `css/app.css`, `src/main.js`,
`src/core/viewsheet.js`.

**Пункт стоит строго после пункта 2, и это не формальность.** Тяжёлая половина
уже написана и принята: `projectView`/`packViewSheet` (`src/core/viewsheet.js`)
проецируют модель обратно в любой из шести видов, а `detectCells`/`cropCell`/
`guessViews` возвращают правленый лист. Здесь добавляется **холст и кисть
поверх готового механизма** и ни одной новой реализации карвинга или проекции.

Всё, что не помечено «**моё**», выведено из `DESIGN.md`, `DECISIONS.md`,
`ROADMAP.md` или из кода. Помеченное «моё» — решение `designer`, которого в
`DESIGN.md` нет; полный список в §10.

## 1. Зачем экран

Пользователь пришёл **поправить сам рисунок, не выходя из вкладки**. Сегодня
продукт требует принести шесть готовых PNG: заметил лишний пиксель на носу
кабины — открывай сторонний редактор, правь, сохраняй, перетаскивай в слот.
Круговой обмен (пункт 2) сократил этот путь до «выгрузи лист — верни лист», но
не убрал из него чужую программу.

- **Главное действие** — выбрать один из шести видов, увидеть его в том виде,
  в каком он идёт в карвинг, и **рисовать по нему теми же инструментами**:
  кисть, заливка, стирка, пипетка (и «Линия», если пункт 1 к этому моменту
  сделан).
- **Второе действие** — **взять недостающий вид из модели** проекцией: рисовать
  можно и там, где пользователь ничего не загружал.
- **Третье и самое тихое** — вернуться к модели и нажать «Собрать модель».
  Пересборка остаётся **явной**, отдельной кнопки под неё не заводится (§4.4,
  обоснование числом).
- **Вторично и потому тише:** подпись с размером рисунка и шагом сетки —
  одна моноширинная строка `.readout`; вход в режим со слота — одна кнопка
  `✎` в уже существующем ряду `.slot-tools`.
- **Не входит:** выделение и перенос области по рисунку (это пункт 1, и по
  рисунку бокс выключается — §6.2); слои (пункт 5); собственный формат
  проекта — рисунок остаётся обычным RGBA-изображением в слоте; правка
  нескольких видов одним жестом; масштабирование и обрезка рисунка внутри
  режима (для этого есть `↻ H V ×` в слоте).
- Правая колонка **не меняется ни на пиксель**, кроме двух подсказок,
  которые в режиме рисунка говорят другое (§6.5).

## 3. Раскладка

Целевые размеры из `DESIGN.md` §5: три колонки `268px | 1fr | 268px`
(`css/app.css:120`), полезная ширина панели 240 px, сжимается центр. Проверять
на **1440×900** и **1024×768**. Мобильной раскладки нет.

Меняются четыре места; пятое (правая колонка) только переписывает две
подсказки.

### 3.1. Окно модели, режим 3D — ничего не меняется, кроме одной пары чипов

```
┌ окно модели ────────────────────────────────────── 904 px на 1440 ─────────┐
│ [3D][2D] │ [Спереди][Справа][Сзади][Слева][Изо]              [− 4× +]      │
│  ↑ новая пара                ↑ как было                       ↑ как было   │
│                                                                            │
│                         (модель, WebGL, #gl)                               │
│                                                                            │
│ Готово: вокселей 2 952 960 · граней 1 118 208                              │
└────────────────────────────────────────────────────────────────────────────┘
```

### 3.2. Окно модели, режим 2D

`#gl` скрывается целиком, на его месте — второй холст `#view2d`
(2D-контекст, `image-rendering: pixelated`). Ряд чипов углов **заменяется**
рядом из шести видов: один и тот же ряд всегда отвечает на вопрос «на что я
смотрю».

```
┌ окно модели ────────────────────────────────────── 904 px на 1440 ─────────┐
│ [3D][2D] │ [Спереди][Сзади][Справа][Слева][Сверху][Снизу]    [− 2× +]      │
│                                                                            │
│              ╔═══════════════════════════════════╗                         │
│              ║ ░░░░ шахматка прозрачности ░░░░░░ ║  ← рамка размещения,    │
│              ║ ░░░░░░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░ ║    1 px, --line         │
│              ║ ░░░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░ ║                         │
│              ║ ░░░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░ ║  решётка --line-soft,   │
│              ║ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ ║  только от 6×           │
│              ╚═══════════════════════════════════╝                         │
│                                                                            │
│ спереди · 142, 87 · #d94f3a                                                │
└────────────────────────────────────────────────────────────────────────────┘
```

Рисунок **центрируется** по окну; зум целый, 1…64, шаг 1 — те же кнопки
`.zoom-chip`, что и в 3D. При входе в режим зум подбирается «вписать» тем же
правилом, что `camera.fitTo`: целое число, не меньше 1, поле 8 % по краям.
Панорама — инструмент `⟳` (в этом режиме он «Панорама», §6.2) и `Ctrl`+тяга,
как в 3D.

**Пусто (нет рисунка):** вместо холста — приглашение по образцу
`#viewport-empty` (тот же класс, тот же центр):

```
│                      Для этого вида ещё ничего не нарисовано.              │
│                    [ Взять из модели ]  [ Чистый лист 256×256 ]           │
│         Модель проецируется обратно через этот вид: около 0.3 с            │
│                          на сетке 256³.                                    │
```

### 3.3. Левая панель, «Исходные виды» — пятая кнопка в слоте

`.slot-tools` было четыре кнопки (`↻ H V ×`), стало **пять**: первой встаёт
`✎`. Ряд прижат к правому нижнему углу слота и при пяти кнопках занимает
5 × 17 + 4 × 3 = **97 px** при ширине слота 117 px — влезает, `.slot-size`
слева не задевается.

```
┌ слот 117×92 ─────────┐
│      СПЕРЕДИ         │  .slot-name, 10 px
│      ┌────────┐      │
│      │ 52×52  │      │
│      └────────┘      │
│ 308×349   [✎][↻][H][V][×] │  .slot-size mono 10 px + .slot-tools
└──────────────────────┘
```

Слот, чей рисунок правлен и ещё не пересобран, получает класс `.slot.edited`:
рамка `1px solid var(--warn)` (**моё**, §10.2) и `title` = `views.edited`.

### 3.4. Левая панель, «Собрать модель» — одна новая строка под кнопкой

```
 240 px ─────────────────────────────────
[        Собрать модель        ]          button.primary, как было
Правлены рисунки: спереди, сверху —       .hint.warn, только когда есть
модель их ещё не видела.                  правленые и непересобранные
```

Строка занимает две строки текста при трёх и более именах видов (48 знаков на
240 px при 11.5 px — это ровно две строки) и исчезает после пересборки. Высота
панели прирастает на **≈ 32 px** только в этом состоянии.

### 3.5. 1024×768

Центр сжимается до 488 px. Рисунок 512×512 при зуме 1× шире окна — это
**нормальное состояние переполнения**: холст панорамируется, чипы видов
переносятся во вторую строку (`.angle-chips` уже `flex-wrap: wrap`), пара
`[3D][2D]` остаётся первой в потоке и никогда не переносится одна. Ничего не
прячется и не сжимается по шрифту.

### 4.2. Порог решётки — **6×**, и это то же число, что и 12× в 3D

`DECISIONS.md` (2026-09-24, решётка): пол читаемости — **6 px**: линия 1 px
плюс просвет 5. В 3D самая тесная клетка под диметрией 2:1 занимает 0.5774
вокселя, отсюда 6 / 0.5774 ≈ 10.4 → порог 12. **В режиме рисунка клетка стоит
к экрану ровно, без ракурса**, множитель 1, и тот же пол даёт порог
**6 px на клетку**. Число не новое — новое только его применение без косого
ракурса.

Клетка на экране = `зум × (пиксели рисунка на клетку)`. Для рисунка 1:1 это
зум; для 308×349 на сетке 256 — `зум × 1.203`, и решётка появляется уже с 5×.

### 4.3. Что именно показывает холст

Показывается **рисунок слота после `↻ H V`**, то есть в той ориентации, в
какой его видит карвинг, в **его собственном пиксельном разрешении**. Правка
ложится в те же пиксели, которые лежат в слоте (`ROADMAP.md`, «Правка меняет
рисунок в слоте»), — ни одного пересчёта разрешения, ни одной потери на
повторной выборке.

Поверх рисунка одной строкой `.readout` сказано, как он ляжет на сетку:

- 1:1 → `308×349 px · сетка 256 · пиксель в клетку`;
- иначе → `308×349 px · сетка 256 · 1 клетка = 1.20 px`.

**Вид, взятый из модели, всегда ровно N×N и не обрезается по содержимому**
(`projectView` так и отдаёт). Обрезка по контуру, как в `packViewSheet`, здесь
запрещена намеренно: полный N×N делает размещение на сетке тождественным и
обходит известный дефект округления `autoPlace` (`BATCH.md`, «Найдено по
ходу» — потеря столбца при противоположной чётности).

### 4.4. Пересборка — по кнопке, а не по отпусканию кисти

Решено числом: карвинг занимает **1.1 / 3.7 / 11.0 с** на 256 / 384 / 512
(`docs/TESTING.md`, `tests/perf`). Даже самая дешёвая рабочая сетка на два
порядка дороже мазка. Пересборка по отпусканию кисти превратила бы рисование в
«мазок — десять секунд ожидания — мазок», а `DESIGN.md` §6 требует полосу
прогресса у всякой работы дольше секунды: пользователь получил бы полосу после
каждого касания.

**Правило:** правка рисунка не трогает модель вовсе. Модель догоняет рисунок
только по нажатию уже существующей `#btn-build` «Собрать модель». Второй
акцентной кнопки на экране не появляется (`DESIGN.md` §2, правило акцента).

**Ловушка из `ROADMAP.md` пункт 5 закрывается тем, что уже есть:**
`#btn-build` идёт через `guardRebuild`/`mayDiscardEdits` (`src/main.js:326`), и
ручные правки модели по-прежнему требуют подтверждения. Ни одного нового
диалога. Сверх этого — §6.6.

## 6. Состояния

### 6.1. Пара `[3D][2D]`

| Состояние | Вид |
|---|---|
| обычное | `--text-dim` на `--overlay`, рамка `--line` |
| наведение | `color: var(--text)`, рамка `--accent-dim` |
| нажатие | без своего вида — переключение мгновенное |
| выбранное | `color: var(--accent)`, рамка `--accent-dim` (`.on`, как у чипов углов) |
| фокус | `outline: 1px solid var(--accent-dim)` (`DESIGN.md` §6, правило 8) |
| выключено | `2D` гаснет, когда **нет ни одного рисунка и нет модели**: проецировать нечего и править нечего. Причина — `.hint` в приглашении пустого окна, а не всплывающая подсказка |

Переключение в 2D **гасит карту расхождений**, если она была включена
(`DESIGN.md` §6, правило 7 — режим просмотра и режим рисунка не совмещаются),
и пишет об этом причиной под флажком карты: `view2d.mapOff`.

### 6.2. Ряд инструментов в режиме 2D

| Инструмент | В режиме рисунка |
|---|---|
| `⟳` орбита | **становится «Панорама»**: подпись и `title` меняются, курсор `grab`/`grabbing`, как было |
| `◉` кисть | работает: красит пиксель выбранным цветом палитры, альфа 255 |
| `▣` заливка | работает: по связной области одного цвета, включая прозрачную |
| `⌫` стирка | работает: делает пиксель прозрачным (альфа 0) |
| `◔` пипетка | работает: берёт цвет пикселя; прозрачный пиксель цвета не даёт и говорит об этом строкой состояния |
| `⬜` добавить | **выключен**: у рисунка нет вокселей, добавлять нечего |
| `⬛` бокс | **выключен**: выделение живёт в объёме (пункт 1) |
| `╱` линия | работает, **если пункт 1 к этому моменту сделан**; если нет — кнопки просто нет, и здесь ничего не меняется |

Две выключенные кнопки объясняются **одной** строкой `.hint.warn` под рядом
(`DESIGN.md` §6, правило 3): `view2d.toolsOff`. Выключенный вид —
`opacity: .45; cursor: not-allowed`, уже есть в `css/app.css:519`.

Курсоры (`DESIGN.md` §6, правило 9, без новых значений): `crosshair` — кисть,
заливка, линия; `cell` — стирка; `copy` — пипетка; `grab`/`grabbing` —
панорама.

### 6.4. Экран: пусто, загрузка, ошибка, переполнение

| Состояние | Что видно |
|---|---|
| **рисунка нет, модель есть** | приглашение `view2d.empty` + `[Взять из модели]` + `[Чистый лист N×N]` + `.hint` `view2d.takeCost` с числом для текущей сетки: **0.04 с** на 128, **0.3 с** на 256, **2 с** на 512 |
| **рисунка нет, модели нет** | приглашение `view2d.noModel`, кнопка «Взять из модели» выключена, «Чистый лист N×N» — активна |

| **проекция идёт** | на сетках **384 и 512** — `.progress` со стадией `view2d.projecting`, доля растёт **по строкам `v`, шаг 1/16 рисунка** (молчание не больше пятой части работы, `DESIGN.md` §6). На 256 и ниже полосы нет: 0.3 с |
| **проекция вернула пустой рисунок** | строка состояния `warn`: `view2d.takenEmpty` — «Этот вид модели не видит ни одного вокселя» |

| **очень длинный текст** | строка состояния однострочная с затуханием справа, важное в первых 40 знаках (`DESIGN.md` §6); список правленых видов переносится максимум в две строки — шесть имён по-русски это 48 знаков |

### 6.5. Правая панель — две подсказки говорят другое

- `#bounds-hint` (флажок «Показывать габариты»): в режиме рисунка тот же
  флажок управляет **решёткой клеток на холсте**, и подсказка называет порог:
  `view2d.gridHint` — «Решётка клеток появляется с 6× — на меньшем зуме линии
  сливаются».
- `#map-hint`: причина `view2d.mapOff`, флажок карты выключен.

Больше в правой колонке не меняется ничего: экспорт, `.obj`/`.glb`/`.vox`,
сохранение — те же кнопки в тех же состояниях.

### 6.6. Обещание, которое экран обязан держать

`ROADMAP.md` пункт 5 («пересборка заменяет ручные правки… правка вида обязана
спрашивать так же, а не молча») закрывается тремя видимыми вещами:

1. **Правка рисунка ничего не рушит в модели** — модель отстаёт, и это
   написано строкой `.hint.warn` под «Собрать модель», а не подразумевается.
2. **Пересборка спрашивает** — существующий `mayDiscardEdits`, без изменений.
3. **Кнопка «Взять из модели» честно называет, что она уносит**: проекция
   везёт силуэт и видимый цвет, не историю, и на противоречивых рисунках круг
   возвращает материал, срезанный `clipContestedSpikes` (+1.05 % на грузовике
   256 — замер пункта 2). Это **та же оговорка, что уже написана** в
   `export.viewsNote`; повторять её целиком нельзя — она длиннее любого места
   в накладке. Поэтому под кнопкой стоит короткая `.hint` `view2d.takeNote` с
   одним предложением, а полный текст остаётся у кнопки экспорта.

## 8. Клавиатура

Новые горячие клавиши (свободны: заняты `v b g e a i r d`, плюс `l` забронирован
пунктом 1):

| Клавиша | Что делает |
|---|---|
| `P` | переключает модель ↔ рисунок (**моё**, §10.5) |
| `1`…`6` | **в режиме рисунка** — выбрать вид: спереди, сзади, справа, слева, сверху, снизу. В режиме модели `1`…`5` по-прежнему углы обзора (**моё**, §10.6) |

Действует общее правило: клавиша молчит, когда фокус в `input`, `select` или
`textarea` (`DESIGN.md`, «Горячие клавиши»).

Порядок обхода `Tab` в режиме рисунка — слева направо и сверху вниз, без
изменений в панелях:

1. шапка (демо, очистить, язык, тема, исходники);
2. левая панель: слоты видов (каждый слот — одна остановка, внутрь стрелками),
   `Нарезать лист…`, сетка, `Вписать`, **`Собрать модель`**, ряд инструментов
   (**одна остановка**, внутрь стрелками, `DESIGN.md` §6 правило 6), кисть,
   два флажка (выключенные пропускаются браузером сами), отмена/повтор,
   палитра (одна остановка);
3. окно модели: **пара `[3D][2D]` — одна остановка**, внутрь `←`/`→`; **ряд
   видов — одна остановка**, внутрь `←`/`→`; зум `−`, `+`; кнопки приглашения
   пустого окна, когда оно показано;
4. правая панель — как было.

Сам холст `#view2d` фокус не принимает — как и `#gl` сегодня: рисовать с
клавиатуры мы не обещаем, а лишняя остановка на неинтерактивном прямоугольнике
только удлиняет путь до правой панели.

## 9. По чему судить снимок

Проверяемые утверждения для `reviewer`. Снимок — встроенная панель
предпросмотра, порт 5173 (`docs/TESTING.md`); **браузер владельца не трогать**.

1. В режиме модели слева вверху окна стоят **две** группы чипов: `[3D][2D]` и
   пять углов; выбран `3D`, он `--accent`, второй `--text-dim`. Акцентных
   заливок на экране по-прежнему **одна** — «Собрать модель».
2. По `P` (или щелчку по `2D`) `#gl` исчезает, появляется холст с шахматкой, а
   ряд углов заменяется **шестью** чипами видов; зум справа остаётся на месте.
3. Загруженный демо-рисунок `front` 12×12 виден целиком, центрирован, с
   решёткой: при 12×12 в окне 904×~820 зум упирается в 64×, порог 6×
   пройден.
4. Кнопки `⬜ Добавить` и `⬛ Бокс` погашены, под рядом стоит **одна** строка
   `--warn` `view2d.toolsOff`; флажки «одна грань» и «зеркало по X» погашены и
   **своей** строки не получают.
5. Слот вида, по которому рисовали, имеет рамку `--warn`, а под «Собрать
   модель» стоит строка `grid.viewsAhead` с именем этого вида. До нажатия
   кнопки счётчик вокселей в `.stats` **не меняется ни на единицу**.
6. Пустой слот в режиме рисунка показывает приглашение с двумя кнопками, и
   подсказка под ними называет **число секунд для текущей сетки** (0.3 при
   256³, 2 при 512³), а не «это может занять время».
7. Наведение на пиксель пишет в строку состояния `вид · x, y · #rrggbb`
   моноширинным; уход указателя **возвращает прежнее сообщение**, а не
   очищает строку.
8. Переключение в режим рисунка при включённой карте расхождений гасит флажок
   карты, и под ним стоит причина `view2d.mapOff`.
9. В светлой теме ни один из новых элементов не носит зашитого цвета: рамка
   `--warn`, решётка `--line-soft`, шахматка `--checker-a/b` переключаются
   вместе с темой.
10. При 1024×768 шесть чипов видов переносятся во вторую строку, пара
    `[3D][2D]` остаётся в первой, холст панорамируется, ничего не обрезано и
    не налезает на зум.

## 10. Решения `designer`, которых нет в `DESIGN.md` («моё»)

1. **Разделитель 1 px `--line` между парой `[3D][2D]` и рядом видов.** В
   накладке впервые встают две радиогруппы подряд; без разделителя они читаются
   как одна из восьми кнопок. Цвет и толщина — существующие.
2. **Правленый и непересобранный слот помечается рамкой `--warn`.** `DESIGN.md`
   даёт `--warn` тексту причины, но не границе. Здесь это ровно та же роль —
   «тут расхождение, и вот где» — и других тихих способов пометить шесть
   миниатюр у нас нет (счётчик на 20×20 запрещён правилом 5).
3. **Подпись кисти в режиме рисунка — `1²`, `3²`, `9²`.** Плоская кисть, и
   куб в подписи был бы враньём. Значения ползунка те же 0…4.
4. **История получает третий вид записи — `view`.** `DECISIONS.md` (2026-09-24)
   узаконил типизацию `{kind: voxels | palette | merge}` именно для таких
   случаев: правка пикселей не меняет ни вокселей, ни значений палитры, и
   воксельная запись её не удержит. Запись — `{kind: 'view', name, rect,
   before, after}`, одна на мазок. Отмена правки рисунка **не трогает модель**
   и не отменяет пересборку — это отдельные шаги, и так их и видно в истории.
5. **Горячая клавиша `P`** на переключение режима. Свободна; `M` отдавать не
   стали — она напрашивается на будущее «зеркало».
6. **`1`…`6` в режиме рисунка выбирают вид.** Тот же ряд чипов — те же цифры;
   шестая цифра в режиме модели не занята, конфликта нет.
7. **Кнопка «Чистый лист N×N».** `ROADMAP.md` обещает только проекцию, но без
   модели проецировать нечего, а рисовать с нуля — прямая цель пункта
   («мы требуем принести готовые PNG»). Лист создаётся полностью прозрачным,
   ровно N×N, со `scale 1` и нулевым смещением.
8. **Порог решётки 6× выведен, а не взят.** Число 6 px читаемости —
   из `DECISIONS.md`; 6× — его прямое следствие при ракурсе 1:1. В
   `DESIGN.md` порога для плоского холста нет.

**В `DESIGN.md` при `/done` внести:** правило «режим рисунка и режим просмотра
не совмещаются» (расширение правила 7 на второй режим); порог решётки 6× для
плоского холста рядом с 12× для косого; `--warn` как допустимый цвет **границы**
у элемента, отставшего от модели; горячие клавиши `P` и `1`…`6`; правило
«тяжёлое действие называет свою цену числом секунд для текущей сетки, а не
словом».

**Вопроса владельцу нет.** Развилка «пересобирать по кисти или по кнопке»
`ROADMAP.md` прямо отдана спецификации и решена числом (§4.4).
